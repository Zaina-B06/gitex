## Build

1. **`llm/` package** (Python, provider-agnostic):
   - `LLMClient` protocol with `complete_json(prompt, schema) -> dict`; one implementation for our provider (Azure OpenAI or whichever we have keys for), plus a `FakeLLMClient` for tests that returns canned outputs.
   - `classify_barrier(text, lang) -> {barrier: Barrier, confidence: float, red_flag: bool, red_flag_type?: str}`. Strict JSON schema; anything invalid or low confidence (< 0.6) → `other`, and the app falls back to the button answer.
   - `render_message(template_id, slots, lang) -> str`: the LLM may only **fill slots** in approved templates (e.g. `{action}`, `{time}`, `{user_reason}`); output is checked against a blocklist (blame words, weight/calorie talk, medical claims) and falls back to the plain template if it fails.
2. **Templates** `llm/templates.yaml`, EN + AR, for: daily action, gentle nudge, drifting check-in, lapsed check-in, comeback welcome, step-up, pause acknowledgement, illness/care message, red-flag support message, Ramadan mode start, heat mode notice. Tone: warm, short, never blaming, no streak language.
3. **Safety lists** `llm/safety.yaml`: red-flag keywords/phrases in EN + AR (+ Hindi/Urdu if time allows) for chest pain, fainting, breathlessness, self-harm, disordered eating; a blocklist for outgoing messages; and the care/escalation messages per red-flag type (point to appropriate care or emergency services; no diagnosis). Mark every Arabic string `ar_reviewed: false`.
4. **Eval set** `llm/eval/barriers.jsonl`: ≥ 80 short check-in texts (EN + AR, mixed dialect and English/Arabic code-switching, typos) labelled with a barrier, including ~10 red-flag cases. Script `python -m llm.eval` prints accuracy, a confusion matrix and red-flag recall (target: red-flag recall = 100%).
5. **Docs skeleton** in `docs/`:
   - `ARCHITECTURE.md` (headings + the diagram description from the PRD)
   - `DATA_SOURCES.md` (table: source, licence, what it's used for; start with "synthetic data generated by sim/" and the LLM provider)
   - `ASSUMPTIONS.md` (Assumptions / Dependencies / Limitations sections, pre-filled from the PRD §15)
   - `SAFETY.md` (screening rules, red flags, escalation, LLM guardrails, employer restrictions)
   - `MODEL_CARD.md` (barrier classifier: intended use, languages, eval results, known failure modes)

## Done when

- The eval script runs on the real provider and red-flag recall is 100% (keyword fallback guarantees this).
- Templates render in EN and AR; blocklisted outputs fall back to the plain template.
- Docs skeleton exists with every section heading in place.
